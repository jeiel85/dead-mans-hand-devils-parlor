# 문서·프로토타입 변경 이력

## Godot 클라이언트 v1.1.0 — 2026-09-10

좁은 화면용 두 번째 레이아웃. [Backlog](BACKLOG.md)의 반응형 항목을 처리했다. **룰·수치·밸런스는 변경 없다.**

### 왜 필요했나

화면은 1280×720 설계 픽셀로 그려지고 전체가 창에 레터박스된다. 설계 픽셀 하나의 값어치는 `창 높이 / 설계 높이`다. 폰(가로 844×390)에서는 0.542라 버튼이 21 px로 줄어 손가락으로 누를 수 없었다.

### 어떻게 고쳤나

- **짧은 창은 설계 높이를 420 px로 낮춘다.** 같은 내용을 더 적은 설계 픽셀로 그리니 픽셀 하나가 0.929로 커진다.
- **좁아지면 배치가 바뀐다.** 응답 버튼은 세로 대신 가로로, 사기 도구는 사이드 패널의 2×2 격자로 옮기고, 캡션·기록 같은 장식은 접는다.
- 컴팩트는 패널을 손으로 놓지 않고 **컨테이너에 맡긴다.** 이 설계 높이에서는 내용이 겨우 들어가서, 밴드를 하나만 잘못 잡아도 다음 패널을 덮는다. 컨테이너는 담지 못하는 것을 겹치지 않는다.

| 폰 가로(844×390) 터치 크기 | 이전 | 이후 |
| :-- | --: | --: |
| 카드 | 42×60 | 54×74 |
| 응답 버튼 높이 | 21 | 45 |
| 사기 도구 높이 | 24 | 45 |
| 상단 아이콘 | 15×14 | 45×45 |

넓은 창은 그대로다. 1280×720의 패널 좌표·카드 크기는 리팩터링 전과 동일하며, 테스트가 그 숫자를 그대로 단언한다.

### 폰트 검사가 잡아낸 것

`extra-glyphs.txt`(서브셋 스크립트와 테스트가 함께 읽는다)를 도입하자, 코드 리터럴로만 쓰이던 글자가 **어느 폰트에도 없다**는 것이 드러났다.

| 글자 | 쓰인 곳 | 조치 |
| :-- | :-- | :-- |
| `✦` | 실린더의 **저주탄 표시** — 색약 이중 표기(GDD §12.4)가 깨져 있었다 | `◆`로 교체 |
| `≡` | 메뉴 버튼 | `▤`로 교체 |
| `⏱` | 타이머 버튼 | `◐`로 교체 |
| `“ ”` | 딜러 대사의 곡선 따옴표 | 서브셋에 포함 |
| `◌̸`(U+0338) | 소리 끔 표시의 결합 사선 | 글자 대신 흐리게 표시로 변경 |

### 테스트

- 넓은 레이아웃의 패널 좌표 고정, 두 모드의 겹침·화면 이탈 금지, 폰 가로 기준 44 px 터치 크기 단언.
- 스크린샷 러너를 두 해상도(1280×720, 844×390)로 돌리고, 실행 중 창 크기를 바꿔 모드가 전환될 때도 패널이 겹치지 않는지 확인한다.
- Godot 33,367건 · Node 28건, 실패 0.


## Godot 클라이언트 v1.0.2 — 2026-09-10

[이슈 #2](https://github.com/jeiel85/dead-mans-hand-devils-parlor/issues/2)의 남은 항목 대응. 룰·수치·밸런스는 변경 없다.

### 고침

| 항목 | 문제 | 조치 |
| :-- | :-- | :-- |
| 15초 도전 타이머 | 벽시계(`Time.get_ticks_msec()`)로 재던 탓에, 탭을 숨겼다 돌아오면 카운트다운을 한 번도 못 보고 그 자리에서 자동 응답됐다 | 프레임 델타로 세고 한 프레임이 먹을 수 있는 시간을 0.25초로 제한한다. 창이 포커스를 잃으면 멈춘다 |
| 연출 큐의 런 무효화 | 애니메이션 대기 중에 새 판을 시작하면, 끝난 판의 효과음·화면 효과가 새 판 위에서 계속됐다 | 모든 대기를 `_pause(초, 토큰)` 하나로 모아 매 대기마다 토큰을 확인한다. 판을 버릴 때 `modal_continue`를 발신해 공개 화면에 멈춰 있던 코루틴도 풀어준다 |

### 넓힌 것

- **크로스 엔진 트레이스**: 시드 5개 → 7개. 딜러 7명 전원과 게임오버·승리 양쪽 종료를 덮는다(1,121 → 1,986 이벤트). `tools/trace.js`가 커버리지가 깨지면 생성 단계에서 실패한다.
- **스크린샷 러너**: 8장 → 12장. 보상을 실제로 클릭해 다음 층으로 넘어가는지, 게임오버·승리 화면이 뜨는지, 타이틀로 돌아갈 때 판이 정리되는지 단언한다.
- **폰트 커버리지 테스트**: 사전의 모든 글자가 번들 폰트에 있는지 검사한다. 넣자마자 실제 누락(♚♛)을 잡았고, Godot은 왕관을 도형으로 그리므로 검사 대상에서 제외했다.

### 줄인 것 · 측정한 것

명조 폰트를 실제로 쓰는 432자로 서브셋했다(`tools/subset-fonts.py`). 고딕은 시드 입력이 자유 입력이라 KS X 1001 전체를 유지한다.

| | 이전 | 이후 |
| :-- | --: | --: |
| 명조 폰트 | 1,796,744 B | 262,692 B |
| `index.pck` (gzip) | 4,573,979 B | 3,697,720 B |
| 첫 로드 합계 (gzip) | 약 14.9 MB | 약 14.0 MB |

**전제가 틀렸던 것**: 이슈에 "첫 로드 46MB"라고 적었지만 실측하면 GitHub Pages가 gzip을 주므로 wasm 39.5MB → 10.2MB로 전송된다. brotli는 Pages가 주지 않는다. 또 "로딩 진행 표시가 없다"고 적었으나 Godot 기본 웹 셸에 스플래시와 `<progress>` 막대가 이미 있다. wasm이 전송량의 대부분이라 더 줄이려면 커스텀 엔진 빌드가 필요하다.

### 세로 화면

세로에서는 고정 1280×720이 3분의 1로 줄어 카드가 24×34 px가 된다(실측). 가로로 돌려 달라는 안내를 띄운다. 가로 폰에서도 버튼 높이는 21~24 px로 44 px 권장치에 못 미치며, 이를 맞추려면 버튼 높이가 설계 기준 81 px여야 해서 반응형 레이아웃이 필요하다. 이슈 #2에 측정치와 함께 남겨 뒀다.

## Godot 클라이언트 v1.0.0 / GDD v1.2.0 — 2026-09-10

웹 프로토타입에서 검증한 룰·수치·AI를 **Godot 4.7 GDScript 클라이언트**로 옮기고, 웹·Windows·Linux 세 플랫폼으로 빌드했다. 룰과 밸런스 수치는 한 줄도 바뀌지 않았다.

### 추가

- `godot/` — 코어 6모듈(rng·data·rules·ai·i18n·save·audio)과 표현 계층(ui_kit·card/cylinder/portrait view·table_screen·modal·main).
- **크로스 엔진 트레이스 검증**: `tools/trace.js`가 JS 엔진에서 5개 시드 1,121개 이벤트를 뽑아 `godot/test/fixtures/traces.json`에 고정하고, Godot 테스트 러너가 재생해 필드 단위로 비교한다. 룰·AI·퍼즈(300런)까지 합쳐 **33,255건 검사, 실패 0**.
- 헤드리스 테스트 러너와 스크린샷 러너. 스크린샷 러너는 실제 마우스·키보드 입력을 밀어 넣고 결과를 단언한다(카드 2장 선택, Enter로 공개 화면 닫기).
- 배포 워크플로 2종: Pages(루트 = JS 프로토타입, `play/` = Godot 웹 빌드), 태그 릴리스(Windows·Linux·Web zip). CI에 Godot 테스트 잡 추가.
- 폰트 2종(Noto Sans KR, 나눔명조 Bold, OFL) 외 외부 에셋 0. 사운드 16종은 런타임 절차 합성.

### 정정 (Godot 클라이언트에서만)
