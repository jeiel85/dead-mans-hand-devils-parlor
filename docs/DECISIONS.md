# 결정 기록 (되돌리기 어려운 결정만)

형식: 배경 → 선택지 → 결정 → 근거 → 되돌릴 때의 비용.

## D-001 · 본 개발 엔진: Godot 4.3+(C#) 권장, Unity 대안 — 2026-09-09 (원본 유지 · 언어는 D-008로 대체)

- **선택지**: Godot 4 C# / Unity 2022 LTS·6 / 웹 기술(Three.js 등)로 본 개발.
- **결정**: Godot 4.3+ C# 우선. Unity는 팀 확대·콘솔 포팅이 확정될 때 재검토.
- **근거**: 1인 개발 이터레이션 속도, 경량 빌드, 웹/모바일 익스포트, 로열티 없음. 2.5D(로우폴리 환경 + 2D 캐릭터)에 충분.
- **되돌릴 비용**: 코어 룰은 순수 로직(D-003)이라 포팅 비용이 낮다. 연출·에셋 파이프라인은 엔진 종속이므로 5주차 이전에 확정해야 한다.

## D-002 · 검증용 웹 프로토타입은 바닐라 JS, 빌드 도구 없음 — 2026-09-10

- **선택지**: 즉시 Godot로 시작 / React·Vite 웹 / 바닐라 ES 모듈.
- **결정**: 바닐라 ES 모듈 + 정적 호스팅(GitHub Pages).
- **근거**: 설계서의 룰·밸런스를 **가장 빨리 플레이 가능한 형태로 검증**하고 링크 하나로 공유하는 것이 목적. 빌드 단계·의존성이 없어야 링크가 오래 살아남는다. 사용자의 다른 저장소 관례(단일 HTML·외부 에셋 0)와도 맞다.
- **되돌릴 비용**: 프로토타입은 폐기 전제. 엔진(`rules.js`)·AI·수치는 C#으로 포팅한다.

## D-003 · 엔진은 순수 함수 + 이벤트 로그, 모든 무작위는 시드 RNG — 2026-09-10

- **선택지**: UI와 로직 결합 / 로직 분리 + `Math.random` / 로직 분리 + 시드 RNG + 이벤트.
- **결정**: 시드 RNG(xmur3 → mulberry32) + 액션이 이벤트를 남기는 순수 엔진.
- **근거**: 같은 코드로 UI·테스트·시뮬레이터·(미래) 고스트 재생기를 돌릴 수 있다. 버그 재현·데일리 시드·세이브(시드 + 액션 로그)가 공짜로 따라온다.
- **되돌릴 비용**: 높음. 고스트·세이브 포맷이 이 결정 위에 서므로 본 개발에서도 유지한다.

## D-004 · 실린더는 테이블 공유 1정, 순차 챔버, 구성 공개 — 2026-09-10

- **선택지**: 《Liar's Bar》식 개인 리볼버(각자 1/6→1/5…) / 공유 1정 + 구성 공개 + 순차 챔버(《Buckshot》식).
- **결정**: 공유 1정.
- **근거**: 1v1 구조에서 정보 게임(남은 실탄 세기)과 사기 도구(거울·납 탄환)가 모두 "다음 챔버"라는 하나의 대상에 걸려 룰이 단순해진다. 다인 테이블 도입 시 재검토.
- **되돌릴 비용**: 중간. `RevolverCylinder`를 플레이어별 인스턴스로 바꾸면 AI의 `pLive` 계산과 도구 효과 범위가 달라진다.

## D-005 · 고스트 데이터는 결정 로그 + 시드, 커서 궤적은 수집하지 않음 — 2026-09-10

- **선택지**: 원본안(마우스 궤적·망설임·시선) / 결정 로그 + 망설임 시간만.
- **결정**: 결정 로그 + 0.1초 양자화 망설임 시간. 옵트인, 익명 기본.
- **근거**: 재생에 필요한 것은 결정뿐이고, 궤적은 입력 장치마다 의미가 다르며 개인정보 리스크만 키운다.
- **되돌릴 비용**: 낮음(필드 추가는 가능). 단, 한 번 수집한 데이터는 되돌릴 수 없으므로 보수적으로 시작한다.

## D-006 · 배포: GitHub Pages, `main` 브랜치 루트에서 직접 서빙 — 2026-09-10 (D-010으로 대체)

- **선택지**: Actions 기반 Pages 배포 / `gh-pages` 브랜치 / `main` 루트(legacy).
- **결정**: `main` 루트. 빌드가 없으므로 배포 파이프라인이 필요 없다.
- **근거**: 사용자의 기존 저장소들과 동일한 방식. 실패 지점이 하나 줄어든다.
- **되돌릴 비용**: 매우 낮음(저장소 설정 한 번).

## D-007 · 인앱 결제·가챠·실화폐 베팅 없음 — 2026-09-10

- **결정**: 유료 단품만.
- **근거**: 도박·자해 묘사와 실구매가 결합되면 등급·플랫폼 정책 리스크가 급격히 커진다(GDD §16 R-2).
- **되돌릴 비용**: 매우 높음(평판·심의). 되돌리지 않는 전제로 설계한다.

## D-008 · Godot 클라이언트 언어는 C#이 아니라 GDScript — 2026-09-10

- **배경**: D-001에서 "Godot 4 C#"을 권장했으나, 실제 착수 시점에 웹 익스포트가 1순위 배포 채널이 되었다.
- **선택지**: (a) C# — 원본 권장, 정적 타입·기존 .NET 자산, (b) GDScript — 엔진 내장, (c) GDExtension(C++).
- **결정**: **GDScript**. C# 재검토 시점은 콘솔 포팅 또는 서버 로직 공유가 확정될 때.
- **근거**:
  - **웹 채널이 1순위인데 .NET 쪽 웹 지원은 보장되지 않는다.** Godot의 C# 빌드는 별도(mono) 에디터·익스포트 템플릿을 쓰고 웹 지원이 오랫동안 미지원/실험 상태였다. 이 프로젝트의 1순위 배포가 GitHub Pages 라이브 데모라 그 불확실성을 감수할 이유가 없다. 표준 4.7.2 배포의 GDScript 웹 익스포트는 실제로 빌드·플레이까지 확인했다.
  - 엔진 코드가 순수 로직(D-003)이라 언어에 거의 의존하지 않는다. 실제 포팅은 `src/rules.js` → `godot/scripts/core/rules.gd` 1:1로 끝났고, 두 엔진의 이벤트 스트림이 5개 시드 1,121 이벤트에서 바이트 단위로 일치한다.
  - 런타임 의존성이 늘지 않는다(.NET 런타임·별도 익스포트 템플릿 불필요). 데스크톱 빌드가 단일 실행 파일로 떨어진다.
- **되돌릴 비용**: 중간. 코어 6파일(rng/data/rules/ai/i18n/save)은 기계적 포팅이 가능하지만, UI 계층 전체(`scripts/ui/`)와 트레이스 픽스처 검증을 다시 만들어야 한다. 웹 채널을 포기한다는 뜻이기도 하다.

## D-009 · v1.0은 2.5D가 아니라 코드로 구성한 2D UI — 2026-09-10

- **배경**: 원본 설계는 "로우폴리 환경 + 2D 캐릭터"의 1인칭 2.5D 살롱을 상정했다.
- **선택지**: (a) 2.5D 씬(3D 환경·카메라·라이팅·모델링 에셋 필요), (b) 2D 테이블 뷰를 `.tscn` 에디터로 작성, (c) 2D 테이블 뷰를 GDScript 코드로 구성.
- **결정**: **(c) 코드로 구성한 2D 테이블 뷰**(1280×720 고정 레이아웃, `stretch/aspect="keep"`).
- **근거**:
  - 검증해야 할 것은 **룰과 긴장감**이지 공간감이 아니다(GDD §15 P1). 2.5D는 아트 에셋이 없으면 착수조차 못 한다.
  - 외부 에셋 0을 유지한다. 카드·실린더·초상·하트는 전부 `_draw()` 절차 렌더링, 사운드는 절차 합성 WAV, 폰트만 OFL 2종.
  - `.tscn` 대신 코드로 만들면 diff가 읽히고 리뷰가 되며, 씬 파일 병합 충돌이 없다.
  - 고정 레이아웃 + `keep`은 창 비율이 달라져도 배치가 무너지지 않는다(늘어난 창에서 위쪽으로 몰리는 `expand` 문제를 실측으로 확인해 교체).
- **되돌릴 비용**: 낮음. 엔진·AI·세이브는 표현 계층과 분리돼 있어 2.5D 씬을 새 표현 계층으로 얹으면 된다. 아트 파이프라인 착수 시(로드맵 5~6주차) 재검토한다.

## D-010 · Pages는 Actions 빌드로 배포, Godot 빌드는 저장소에 커밋하지 않음 — 2026-09-10

- **배경**: Godot 웹 빌드는 `index.wasm` 하나가 약 38MB다. D-006의 "main 루트 직접 서빙"을 유지하려면 이 바이너리를 커밋해야 한다.
- **선택지**: (a) 빌드 산출물을 커밋(legacy Pages 유지), (b) `gh-pages` 브랜치에 푸시, (c) Actions에서 빌드해 artifact로 배포.
- **결정**: **(c)**. 워크플로가 Godot 리눅스 바이너리와 익스포트 템플릿을 받아 헤드리스로 빌드하고, 저장소 루트(JS 프로토타입)와 `play/`(Godot 빌드)를 한 artifact로 배포한다.
- **근거**: 38MB 바이너리를 커밋할 때마다 저장소 히스토리가 영구히 커진다. 클론 비용은 되돌릴 수 없다. 소스와 산출물이 어긋날 여지도 사라진다.
- **되돌릴 비용**: 낮음(저장소 Pages 설정 한 번). 단, 한 번 커밋한 대용량 파일은 히스토리에서 지우기 어려우므로 커밋하지 않는 쪽을 기본으로 둔다.
